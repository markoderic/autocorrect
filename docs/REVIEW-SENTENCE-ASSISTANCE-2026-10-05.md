## Findings in the new batch

1. **[P2] Analysis requests can overlap despite the single-request requirement.** `Sources/AutoCorrect/SentenceAssistant.swift:86-100` cancels the old Task and immediately starts another. Cancellation is cooperative; no running-request gate waits for the analyzer to finish. The held-analyzer regression observes two outstanding requests. The existing out-of-order test explicitly expects both to be pending. Keep one actual invocation active and coalesce the next request until completion/cancellation is acknowledged. Late result rejection alone does not bound model work.

2. **[P2] Editing during analysis can publish an obsolete suggestion.** `SentenceAssistant.swift:58-66` only resets the pause timer; it does not invalidate the request ticket. `finish` at lines 104-121 validates against the captured sentence without a fresh context read. Removing/changing the sentence while a held request runs still publishes its result. Popup rendering may later withdraw it if the context read succeeds, but unreadable text returns true at line 139 and leaves stale menu state. Apply has a separate context guard, so this reproduction does not demonstrate an unsafe edit. Revalidate before publishing, and hide/disable unverifiable results until fresh evidence exists.

3. **[P2] Apply discards the suggestion and reports it applied before an edit succeeds.** `Sources/AutoCorrect/CorrectionEngine.swift:233-236` calls `consumed` before `perform`. A valid suggestion near the start of a sentence with more than 96 UTF-16 units after the span cannot pass the existing transport. Clicking Apply leaves the text unchanged, removes the suggestion, and leaves sentence status saying applied. Keep it pending until verified completion; report unsupported placement or failure honestly. Validate applicability before offering Apply where possible.

4. **[P2] Pause-based grammar assistance excludes normal unpunctuated chat.** `Sources/AutoCorrectCore/SentenceSuggestions.swift:100-105` demands a final `.`, `?`, or `!` for both boundary and pause triggers. A 1.5-second pause after `She don't like the new design` produces no analysis. It also skips sentences ending in closing quotes or parentheses. This is documented by Claude but falls short of the requested pause/context behavior. Add a bounded pause analysis route without automatically inserting terminal punctuation or treating ordinary fragments as errors.

5. **[P2] Sentence proposals bypass ignored-word protection.** `SentenceAssistant.swift:115-118` filters category and dismissal only. In the engine regression, a token explicitly added to ignored words is still offered for replacement by sentence analysis. Integrate user-dictionary/occurrence protections before display and Apply. No claim here that all contextual grammar involving an ignored token must be disabled; at minimum the explicitly protected replacement span must be honored.

## Owner-reported fundamentals (pre-existing, still unresolved by this batch)

- **Unfinished-word backspace reproduced.** Type `tex` slowly into an empty field; immediate capitalization produces `Tex`. Backspace once, then type `h `: actual `Teh `, expected `The `. The same sequence with early capitalization disabled produces `the `, and ordinary `teh ` without deletion produces `The `. A posted first-letter capitalization is registered as a normal correction (`CorrectionEngine.swift:1274`, production counterpart `1315`). Delete marks that record, then `ManualRewriteProtection.swift:79-85` sees the completed token differ from the saved single-letter replacement and suppresses spelling. A casing-only edit while a word is incomplete must not mean that later spelling edits were deliberately rejected. Preserve explicit Undo and real spelling reversals.
- **Joined words reproduced:** both `Rightnow ` and lowercase `rightnow ` at field start remain `Rightnow ` instead of `Right now `.
- **Mid-sentence casing reproduced:** `We meet tuesday ` stays lowercase; `Use claude ` stays lowercase. Fresh-field `claude is done ` and `tuesday ` capitalize in the injected engine tests. Therefore the owner's first-word miss in Codex still needs live field/typing evidence; those passing injected tests do not disprove it.
- **Closing parenthesis is not implemented.** There is no dedicated unmatched-opener suggestion or double-space acceptance route. Current validator requires replacements to begin and end with letters, so it cannot offer an end-of-span `)` insertion. Proposed future behavior: offer a reviewable closing-parenthesis hint after enough context, with explicit acceptance. Do not silently assign double-space to `)` without a coherent typing/Undo interaction design. This is new requested scope, not a regression attributed to Claude.
