Version metadata is unchanged (the dev build still says 0.3.9). Read with the work-log entry of the same date.

- **213 automated tests passed, 0 failures, 1 skipped (the gated evaluation)**, `swift test --build-system native`; baseline before the batch was 194/0/1. 19 new tests. One existing expectation revised with its reason recorded in the test file: a curly-apostrophe source (`doen’st`) now keeps the curly style (`doesn’t`), matching the existing `i’m → I’m` rule; straight input still yields a straight apostrophe.
- **Reproduction before changes (same machine, native checker):** `odnt` is natively misspelled with correction `don't`, but the general gate rejected it (two edits: transposition plus apostrophe) and the damaged-contraction rule required five letters and a matching first pair; `ODNT` is *accepted* by the native checker (treated as an acronym, guesses `ODST/ODDEST`); `h` alone had no candidate path; `Teh`/`Speoll` were never tokenized by the existing-text scan, so a capitalized first word's typo could not keep a mark after the debounced scan replaced the region's marks.
- **Field-start capitalization (`Capitalize sentence starts`, same stored key `capitalizesAfterPeriod`, default on, saved choice preserved).** Immediate timing: a lowercase letter typed as the first word of a session schedules one bounded read; if the snapshot is nothing but optional whitespace/openers plus the word typed in this session, the control is an `AXTextArea`, and the field's reported length (`AXNumberOfCharacters`, else the bounded `AXValue`) ends at the caret (one trailing line break tolerated), the word is recased through the normal prepared-edit path (`h → H`, `he → He` when the second letter arrived first). Any other finding settles the session with no further reads. A fast next key invalidates the edit as usual; at most three immediate attempts, then the completed-word fallback (`hello  → Hello `) applies with the same evidence. Deliberately deleting the capital and retyping lowercase is protected by the existing occurrence-level manual-rewrite record; undo uses the existing anchor and a new caret-end plan. Canonical casing still wins for the completed token (`iphone → iPhone`, `github → GitHub`); ignored words and exact custom replacements keep priority; single-line fields, combo boxes, windows not starting at offset zero, emoji/backtick/path prefixes, pasted text and capitalization-off are never capitalized. Paragraph starts, paste and emoji prefixes are **unchanged** (no capitalization) by design in this batch. The Settings “Try it here” preview keeps its mid-document semantics and does not demonstrate field-start timing.
- **Short contractions.** `EnglishWritingRules.typoReplacement` now admits four-letter keys and swapped first pairs with stricter evidence: both every typed letter preserved (a transposition) **and** the native recommendation (or top guess when it is absent) naming the contraction. Native evidence on this Mac: `odnt/dnot → don't`, `cnat → can't`, `wnot → won't`, but `dotn → down` (abstains here; the general one-edit gate still accepts `down`, unchanged baseline). `dent`, `font`, `donut`, `dnt`, `odnts`, `Marko`, `dont.txt` stay untouched; `cant`/`wont` remain the documented prose defaults. All-caps forms are handled by a contextual rule that needs the next word to be an all-caps dictionary word and, for a transposed key, the native correction of the lowercase form: `ODNT DO THAT → DON'T DO THAT`, `DONT DO → DON'T DO`, `I CNAT GO → I CAN'T GO`; `ODNT ` alone, `ODNT XYZ `, `ODNT Do `, `ITS A `, `NASA DO ` abstain. It lives under “Check surrounding context” and honors ignored words and custom replacements.
- **Capitalized typos stay detectable.** `SpellingScan` tokens now include an Initialcase word only where a sentence starts (the field's first word when the scanned window starts at offset 0, or after `. ? !` or a line break); detection still comes from the native checker and the engine's name/ignored/custom filters. `Speoll next` at the field start keeps its mark through the scan; `Marko met Higgsfield` yields none (native accepts Marko; Higgsfield is mid-sentence); `Higgsfield met Speoll` marks `Higgsfield` (it is **not** in the bundled lexicon; before this batch only its capital letter kept it unmarked) and the owner can add it to Ignored Words; all caps and mixed case are never marked. Detection is not replacement: a typed capitalized word without a confident repair is marked, never rewritten.
- **Development build:** `VERSION=0.3.9 ./scripts/build.sh` with the Apple Development identity, universal `x86_64 arm64`, `codesign --verify --strict` valid after clearing Finder metadata that the iCloud Documents folder attaches to `dist/`. The archive written beside it (`dist/AutoCorrect-0.3.9-universal.zip`, SHA-256 `bf7f3828…599b2`, 1,703,880 bytes) is a **dev-signed build of uncommitted code, not a release artifact**, and it replaced the unpublished 0.3.9 archive recorded on September 30 (`54b24f21…`); the installed app was not touched.
- **Real editors: BLOCKED this session.** The desktop-control request for TextEdit and the Codex composer was denied (owner absent), the Chrome tools synthesize input that bypasses the event tap, and Claude's own desktop app cannot be driven by the tool. No field-start, contraction or underline behavior has been observed in a real editor yet. Exact manual checks are listed in the work log.
- **Responsiveness (static comparison; live measurement blocked).** Baseline: letters without a delimiter caused no Accessibility reads. Now: the first word of each typing session (after a click, navigation, deletion or focus change) causes one bounded snapshot read on its first lowercase letter; in a field with existing text that read settles the session and nothing else changes. In an empty text area: that read, one length attribute read (plus one bounded value read in editors without a count), the edit, and one more read after verification; rapid typing adds at most two further attempts. Reads made only for this check queue no scan or render. The all-caps rule adds one or two native checker calls only when the last two tokens are all caps. No change to idle behavior; battery/sustained CPU not inferred.

Checked September 30, 2026 on the development Mac (macOS 27.0.1, Swift 6.4, Apple silicon). 0.3.8 was built but never published; its changes are included in 0.3.9 and its section below still applies.

- **193 automated tests passed, 0 failures, 1 skipped (the gated evaluation).** 19 new tests: the bounded mark model (insert/evict/remove/shift/reconcile/replace/truncate), existing-text tokenization (structured tokens, names, caps, quotes, the word at the caret), overlay placement with injected geometry (wrapped words, off-view words, missing bounds, clipping), and engine bookkeeping through the real native checker (scan policy, accumulation across typing, deletion, field switch, ignore/override/toggle, edits shifting marks, corrected words never marked).
- **Evaluation regression:** the held-out evaluation gives exactly the 0.3.8 numbers (development 1746 correct / 106 false, held-out 1776 / 77, isolated context); automatic correction rules are unchanged in this release. As required by the underline prompt, this corpus is now development/regression evidence, not an independent check.
- **Diagnosis before changes:** with TextEdit's own underlines off, the installed 0.3.8 drew one mark at a time, hidden by the next keystroke or after five seconds, never for existing text. A confounder was found in the verification method: the desktop-control tool filters screenshots to granted apps and cannot grant an agent app, so AutoCorrect's overlay is blank in every capture, and `screencapture` from the shell lacks screen-recording permission. Rendering evidence therefore combines trace phases, the window server's list of on-screen windows (panel bounds versus the AX word bounds), and an in-app bitmap render count of red pixels under `--trace`. A visual confirmation by a person is still requested.
- **Design.** Detection, correction and rendering are separate: `SpellingMarkSet` holds ≤32 marks per field as absolute UTF-16 locations plus the flagged word; `SpellingScan` decides which tokens may carry a mark; `SpellingIndicator` draws every placed mark in one click-through floating panel from per-mark AX bounds, rejects wrapped words and clips to the scroll area/window; `FieldObserver` subscribes to AX focus, value, selection, window move/resize and deactivation notifications; `AccessibilityText.focusedTextRegion` reads a bounded region (editor's visible range ≤2,048 units, else 768 before/256 after the caret) for scans; the engine adds marks for detected misspellings without an applied repair, reconciles them against each fresh window, shifts them on verified edits, drops them on deletion/ignore/undo/deliberate retype, and clears them on toggle, pause, focus change and app switch. Renders and scans are debounced (120/500 ms after typing, 250/450 ms after clicks and scrolls). Contextual grammar doubts are never underlined.
